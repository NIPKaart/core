# Collector and import integration contracts

Inventory for [#1272](https://github.com/NIPKaart/core/issues/1272), within [#1269](https://github.com/NIPKaart/core/issues/1269). Inspected on 2026-09-26: core `07c4fcf`, disabled-parking `2d41ed6`, offstreet-parking `909e68c`. This describes repository behavior and accepted direction, not evidence that a collector or import is deployed in production.

[ADR 0002](../adr/0002-core-owns-publication-collectors-deliver-snapshots.md) owns the boundary: reusable packages retrieve source data; collectors select, normalize and deliver complete source-qualified snapshots; core validates, compares, reviews and publishes. Collectors are not public API clients and must not own core publication state or database writes. The legacy offstreet writer below has not yet converged on that boundary.

## Contract inventory

## Municipal contract ownership and compatibility

The [data delivery contract](data-import-contract.md) remains authoritative for field semantics, source mappings, limits, storage mechanics and recovery. Core owns acceptance and publication rules; `disabled-parking` owns producing compatible files and retaining pending bytes. Changes to `format`, dataset identity, selection or source-field meaning require a coordinated producer/consumer change and a reviewed mapping. Unknown formats are rejected; there is no automatic schema negotiation or public API compatibility promise. Existing dataset codes have no legacy aliases or automatic migration: handle registered datasets and pending files explicitly before switching them.

Both manual and machine intake converge on the same validator and staging logic. Delivery identity is scoped to the dataset and UUID, with SHA-256 of the exact bytes: identical retries reuse status, changed bytes conflict, and a new unchanged snapshot records receipt without duplicating parking records. Publication additionally checks retrieval ordering; equal timestamps with different delivery IDs conflict. Preserve original source claims and local corrections. Eindhoven remains intake/review-only while its publication blockers remain unresolved.

Collector pending bytes are durable transport state; core alone retains import/review/publication state. “Stateless collector” in ADR 0002 does not mean discarding a pending delivery after an interrupted upload. See the [operational guide](collector-staging.md) for deployment and retention; repository implementation is separate from VM, credential and recovery acceptance.

## Offstreet convergence still required

The legacy code mixes facility metadata and live counts in SQL writes, derives identity from coordinates, requests Hamburg with a fixed limit of 40, and converts unknown Amsterdam counts to zero. It provides no completeness evidence equivalent to the municipal contract. These are observed migration gaps, not a description of a running deployment or a new supported contract.

Before connecting offstreet to current core, accept a source mapping and payload that separate facility identity/metadata from live observations. [ADR 0007](../adr/0007-offstreet-live-data-is-facility-wide-and-freshness-aware.md) owns their meaning: general occupancy does not prove an accessible bay is free; unknown counts stay unknown; observations need timestamps and source-specific freshness; stale observations do not delete the facility. Define cadence, observation ordering/expiry and replay rules separately from complete facility snapshots. Reuse municipal transport mechanisms only where these semantics actually match. Core currently has offstreet display/visibility management and sample seeders, but no offstreet delivery receipt, validator or import-review pipeline.

## Separate from web transport and public APIs

Under [ADR 0010](../adr/0010-separate-web-application-endpoints-from-public-api.md), `/map/...`, `/destinations/...`, `/profile/favorites/...` and `/app/...` serve the first-party web application. Municipal upload/review and offstreet visibility controls belong here even when their inputs are import files or their responses are JSON. Their session/policy/CSRF behavior must not be reused as machine credentials. Collectors must not automate these routes or call discovery to synchronize imports.

`routes/api.php` currently declares no routes. There is no collector upload HTTP API and no external read API. [ADR 0011](../adr/0011-defer-external-api-and-bulk-data-access.md) defers external access; `/api/v1` remains reserved. A future public API needs its own explicitly accepted authentication, versioning, compatibility and data-exposure policy. Neither private R2 access nor successful import gives consumers a supported read/export interface, and the municipal format identifier does not reserve or define a public API version.
